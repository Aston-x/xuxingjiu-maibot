# 架构与部署

> **2026-11-10 状态**：QQ 侧冻结为最终公开快照，链路保留但不与 Telegram 强制绑定启动。
> SnowLuma 已转私有、后续不再更新；Telegram 以并行适配器接入，验收通过前不切掉 QQ。

## 运行时拓扑（QQ + Telegram 双栈过渡）

```
QQ 桌面端 ──hook──▶ SnowLuma ──OneBot v11──┐
                                           ├──▶ MaiBot 插件运行时 / Planner / Replyer
Telegram Bot API ──HTTPS 长轮询──▶ Telegram adapter ┘
                                                  │
                         ┌────────────────────────┼──────────────────────┐
                         ▼                        ▼                      ▼
                   memfade 记忆              ComfyUI:8188          GPT-SoVITS:9880
                   日记 / 表情 / 安全          画图                  按需启动
```

关键点：

- QQ 侧保留现有 SnowLuma + 独立 QQ 实例；迁移期间不卸载、不重启这条链路。
- Telegram 使用独立适配器，平台标识为 `telegram`，与 `qq` 的账号、会话和消息 ID 分开。
- 两个适配器可以同时在线；入站会话由宿主平台身份与会话 ID 分开，不合并私聊上下文。
- SnowLuma 已停止公开更新，因此 Telegram 是后续维护重心的候选；
  是否停用 QQ 由验收结果决定，不把“迁移”等同于立刻下线。

## 端口

| 端口 | 谁 | 说明 |
|---|---|---|
| 3000 / 3001 | SnowLuma | OneBot HTTP / WS；3001 要 bot 号登录成功后才开 |
| 5099 | SnowLuma | 它的 WebUI（账号 admin，密码在 `credentials.json`） |
| 8000 | MaiBot 旧版 WS | 本机通常不单独监听，判活不要用它 |
| 8001 | MaiBot WebUI | 大脑判活只认这里 |
| 9880 | GPT-SoVITS | api_v2，TTS 插件依赖它 |
| 8188 | ComfyUI | 画图后端，**吃显存也吃内存** |
| 18650 | MaiWork | 跑在插件 runner 里 |
| 无本地端口 | Telegram adapter | Bot API 长轮询，不需要公网 Webhook |

## 内存纪律（本机 16 GB 的实测结论）

**物理可用内存常年只剩 1~2 GB 属于正常水位，判断资源要看“提交可用”而不是物理可用。**
ComfyUI 实测启动前后提交占用约 4.3 GB；旧文档写的 6.8~11.8 GB 已过时。
Windows 页面文件重启后可能停在 16 GB 种子值，因此提交上限会明显变小。

正确的起服务顺序：先起 QQ/协议端与 MaiBot → 再按需起 ComfyUI 或 GPT-SoVITS。
画图和语音启动器都有提交内存闸门与保险丝；资源不足时先杀自己，不牺牲 MaiBot。

> 2026-10-22 实测：Windows 事件日志 Event ID 2004（资源耗尽）记录了一次，
> 当时 MaiBot + GPT-SoVITS + ZenlessZoneZero（8.9 GB）同时在跑 → MaiBot 直接被杀。

Embedding 走云端，不启用本机 Ollama。现行长期记忆由独立 **memfade** 插件负责；
宿主内置 A_Memorix 的自动写回与自动检索必须保持关闭，避免两套记忆并行。

## 目录布局

```
MaiBot/                      MaiBot 本体（上游 clone）
├─ config/                  配置（.gitignore 忽略，只在本地）
├─ plugins/                 插件（.gitignore 忽略；含 QQ / Telegram 适配器）
├─ data/                    运行时数据：MaiBot.db、插件持久化、聊天记录
├─ logs/                    日志（含 maisaka_prompt/ 的提示词快照，排障很有用）
├─ src/                     核心代码
└─ .venv/                   Python 环境
```

## 排查入口

| 现象 | 先看哪里 |
|---|---|
| 她回得不对 / 回得断 | `src/maisaka` 链路 + `logs/maisaka_prompt/llm_error/` 下最近的 json（有 `workflow_purpose` / `api_provider` / `error.message`） |
| 消息凭空消失 | 平台适配器的 token / 鉴权头；QQ 的 OneBot token 要放在 `Authorization: Bearer <token>` |
| 说话像机器人 / 不像人 | `config/bot_config.toml` 的 `[personality]` 三段 |
| 记得太多 / 反复提起 | memfade 的 `profile_mode` / `recall_alpha`；同时确认 A_Memorix 仍关闭 |
| 私聊内容跑到群里 | 见 [`插件补丁说明.md`](插件补丁说明.md) 第 3、4 条 |
| 插件配置改了没生效 | 改 `config.toml` 是热重载的，但**改插件代码要重启**；WebUI 读回的是运行时值 |
| Telegram 不回 / 不连 | 插件配置里的 Token、代理、`getUpdates` 错误；机器人是否被 Webhook 占用；私聊/群聊白名单是否放行 |
