# 架构与部署

## 运行时拓扑

```
┌──────────────┐   hook    ┌───────────────┐  OneBot v11   ┌────────────────┐
│  QQ 桌面端   │ ───────▶ │   SnowLuma    │ ───────────▶ │      MaiBot    │
│ (人用的主号)  │          │  (协议端,闭源) │  HTTP:3000    │  (大脑,GPL-3.0) │
└──────────────┘          │  WS:3001      │               └────────┬───────┘
┌──────────────┐          └───────────────┘                        │
│  QQ 桌面端   │ ───────▶ (bot 号,单独实例+被静默)                  │
│ (bot 用)      │                                                  │
└──────────────┘                                                  │
                                                          ┌────────▼───────┐
                                                          │  插件（30 个）  │
                                                          │ 记忆 / 日记 /   │
                                                          │ 语音 / 空间 /   │
                                                          │ 好感度 / 表情   │
                                                          └────────┬───────┘
                                                           ┌───────┴────────┐
                                                     GPT-SoVITS:9880   模型 API
```

关键点：

- **QQ 桌面端照常跑**，人用的主号是个正常桌面 QQ；
- bot 号是**独立的第二个 QQ 实例**，靠静默器把它的窗口藏起来（主号必须完好）；
- **SnowLuma 只 hook、不替换 QQ 入口** —— 这是与 NapCat 互斥的两条路，
  换过去要重启 QQ 换注入方式，代价远大于收益；
- MaiBot 只讲 OneBot v11，所以**协议端可以随时再换**。

## 端口

| 端口 | 谁 | 说明 |
|---|---|---|
| 3000 / 3001 | SnowLuma | OneBot HTTP / WS |
| 8000 / 8001 | MaiBot | 主服务 / WebUI |
| 5099 | SnowLuma | 它的 WebUI（账号 admin，密码在 `credentials.json`） |
| 9880 | GPT-SoVITS | api_v2，TTS 插件依赖它 |
| 8188 | ComfyUI | 画图后端，**吃显存也吃内存** |
| 11434 | Ollama | 本地 embedding（16G 机器上建议改用云端 embedding，见下） |

## 内存纪律（本机 16 GB 的实测结论）

**ComfyUI 闲置时私有内存仍占 6.8~11.8 GB**（模型权重已换出到页面文件，但提交量不释放）。
后果是 MaiBot / Ollama / SnowLuma / api_v2 一起起不来 —— 表现是「起不来」而不是「报错」。

**正确的起服务顺序**：先停 ComfyUI → 起 Ollama/SnowLuma/MaiBot/api_v2 → 最后起 ComfyUI。

> 2026-10-22 实测：Windows 事件日志 Event ID 2004（资源耗尽）记录了一次，
> 当时 MaiBot + GPT-SoVITS + ZenlessZoneZero（8.9 GB）同时在跑 → MaiBot 直接被杀。

**Embedding 建议走云端**：16 G 机器装不下 Ollama 时，把
`config/model_config.toml` 里的 embedding 模型指向一个 OpenAI 兼容的
`/embeddings` 端点，并**填上 `[model_task_config.embedding].model_list`**
（这个列表留空的话，记忆内核会直接报「embedding 任务未配置模型」）。

## 目录布局

```
MaiBot/                      MaiBot 本体（上游 clone）
├─ config/                  配置（.gitignore 忽略，只在本地）
├─ plugins/                 插件（.gitignore 忽略）
├─ data/                    运行时数据：MaiBot.db、插件持久化、聊天记录
├─ logs/                    日志（含 maisaka_prompt/ 的提示词快照，排障很有用）
├─ src/                     核心代码
└─ .venv/                   Python 环境
```

## 排查入口

| 现象 | 先看哪里 |
|---|---|
| 她回得不对 / 回得断 | `src/maisaka` 链路 + `logs/maisaka_prompt/llm_error/` 下最近的 json（有 `workflow_purpose` / `api_provider` / `error.message`） |
| 消息凭空消失 | 平台适配器的 OneBot token（`Authorization: Bearer <token>`，不是裸 token） |
| 说话像机器人 / 不像人 | `config/bot_config.toml` 的 `[personality]` 三段 |
| 记得太多 / 反复提起 | `config/bot_config.toml` 的 `[a_memorix]`（阈值、衰减、重锚） |
| 私聊内容跑到群里 | 见 [`插件补丁说明.md`](插件补丁说明.md) 第 3、4 条 |
| 插件配置改了没生效 | 改 `config.toml` 是热重载的，但**改插件代码要重启**；WebUI 读回的是运行时值 |
