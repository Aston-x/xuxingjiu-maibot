# 语音流水线：给自己训一个角色音色

做法记录。**不含音频素材，也不含模型权重** —— 两者都另有出处，且素材是网友上传的。

## 目标

让角色会说话、会唱歌，并把音色调整为某个经授权的私人参考音色。
公开仓库只记录方法，不记录训练素材、角色名或权重。

## 路线选择：先查社区，再自己训

1. **先翻 HuggingFace 的 `gpt-sovits` 标签**（300+ 社区角色模型）。
   v2ProPlus 的权重可以直接喂给 v2Pro 的 api_v2（`/set_gpt_weights` + `/set_sovits_weights`）。
   ⚠ 找模型时优先看**有没有参考音频**（推理必须有 3~10 秒音频 + 对应文本）。
2. **目标音色不一定已有现成模型**。没有匹配项时再考虑自训，并先完成素材授权检查。

## 素材获取的现实

| 渠道 | 结果 |
|---|---|
| YouTube **视频页** | 过不去。bot 检测拦死，yt-dlp 各种 player_client / 浏览器 cookie 全试过；Invidious / Piped 公共实例 19 个全废 |
| YouTube **搜索 API** | 能过 → 说明是视频页被拦，不是整个站点 |
| **B 站** | **能下**。`yt-dlp -f ba` 正常；搜索 API 之前返 412 是**临时风控**，过一阵就好 |

> ⚠ **下载到的是谁，要靠转写核对，不能看标题。**
> 同名角色、同名声优和搬运视频经常互相混淆；混进错误说话人会把音色彻底带跑。
> 公开文档不记录具体人物、作品或素材链接。

## 流水线（GPT-SoVITS v2ProPlus 微调）

```
原始 wav
  └─ 转 32k 单声道
       └─ slicer2 切片（>=4s 一段）
            └─ whisper 转写拿文本
                 └─ .list  (wav|说话人|语言|文本)
                      └─ 1-get-text.py     → 3-bert（只有中文需要）
                      └─ 2-get-hubert-wav32k.py → 4-cnhubert / 5-wav32k
                      └─ 2-get-sv.py      → 7-sv_cn（说话人向量，v2Pro 必需）
                      └─ 3-get-semantic.py → 6-name2semantic
                           └─ s2_train.py（SoVITS）+ s1_train.py（GPT）
```

### 几个会踩的坑

- **发行版是推理精简版**：`GPT_SoVITS/configs/` 是空的，`s2v2ProPlus.json`、
  `s1longer-v2.yaml` 要从上游取；`7-sv_cn` 依赖的 ERes2NetV2 权重、
  `pretrained_models/sv/` 也要自己补。
- **`runtime\Lib\site-packages\users.pth` 里写死旧盘符** → 搬过盘之后
  `from text.cleaner import ...` / `from tools.my_utils import ...` 全挂。
  改这个文件（且必须 UTF-8 无 BOM）。
- **所有脚本的 cwd 必须是仓库根**：`tools/i18n/i18n.py` 用 `os.path.relpath(__file__)`，
  跨盘会 `ValueError: path is on mount 'G:', start on mount 'B:'`。
- **上游 `tools/slicer2.py` 的 CLI 本身是坏的**：`slice()` 返回
  `[waveform, start_ms, end_ms]` 三元组，main() 却按 ndarray 用 `chunk.shape`。
  正确用法是**当库 import `Slicer` 类**（上游 WebUI 也是这么用的）。
- **`2-get-hubert-wav32k.py` 用 `inp_wav_dir + 文件名` 拼路径** → 切片必须摊平到一个目录。
- **`kaldi` 不在 PyPI**：但上游只用了 `Kaldi.fbank(wav, num_mel_bins=80,
  sample_frequency=16000, dither=0)`，`torchaudio.compliance.kaldi.fbank` 就是它的
  官方 Python 复刻，写个 3 行 shim 转发即可，不用装编译型的 pykaldi。
- **训练前必须腾内存**：16 G 机器上 ComfyUI + api_v2 + 训练一起跑会
  `numpy ArrayMemoryError: Unable to allocate 3.13 MiB`（提交内存被占满，不是显存问题）。
- **`s1_train.py` 会自动续训**：`logs_s1/ckpt/epoch=N-*.ckpt` 存在就接着跑，
  `max_epochs` 已满会秒退（看起来像"训练秒完成"其实是没训）。

## 验收：别只靠"听着像"

两个**客观**指标：

1. **可懂度** —— 合成后用 faster-whisper 反查，看识别结果是否与原文**逐字一致**。
   （本机实测中/日文各句全部逐字命中。）
2. **音色相似度** —— 用 `GPT_SoVITS/eres2net` 的 ERes2NetV2 算说话人向量余弦。
   ⚠ 它要**fbank 特征**不是裸波形。
   （本机实测会同时保留基线模型与自训模型的对比，不把单一相似度当作听感结论。）

## 接进 MaiBot

插件侧要三样东西：

- `ref_audio_path` + `prompt_text` + `prompt_lang`（说话参考音）
- `gpt_weights` / `sovits_weights`（热切音色，api_v2 支持运行时切换）
- 想让 `sing` 走**真唱**的话，再给一段**真实唱过的**参考音频 + 对应歌词
  （本机用的是角色本人唱过的那首歌的片段），并把歌词语言设成训练语言。

> `sing` 没有唱段参考音时会退化成「用说话音色带唱腔念」，
> 这时返回文案会**明确说明** `real_singing: false`，不糊弄。
