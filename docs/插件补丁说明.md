# 四个补丁说明

每个补丁都对应一个**实测可复现**的问题，都很小、都很局部。
上游 MaiBot 没修的我们补，上游已经修的我们就别打（见每条的「上游状态」）。

---

## 1. `core-platform-io-group-target-fallback.patch`

**改哪**：`src/platform_io/manager.py`

**现象**：聊天中途**卡住 40~50 秒**，一天实测 9 次。

**根因**：
群会话的出站消息**不一定带 `group_info`** —— 插件主动触发（主动开口）那条就没有。
原代码只读 `group_info.group_id`：

```python
chat_type = "group" if group_info is not None else "private"
target_id = (group_info.group_id if group_info is not None
             else str(additional_config.get("platform_io_target_user_id") or "").strip())
```

`group_info` 缺失时 → `chat_type=private` + `target_id=""`
→ `adapter_policy` 判 **`missing_target_id`** → **直接 DROPPED** → 重试才送达。

而 `send_service._inherit_platform_io_route_metadata` 其实**已经把群号写进
`additional_config`** 了（`platform_io_target_group_id` / `platform_io_target_user_id`），
等于把已经继承下来的目标丢在地上。

**修法**：`group_info` 缺失时回退到已继承的群目标，再回退到私聊目标。

**上游状态**：截至 2026-10-24 的 `origin/main`，`manager.py` 里仍然是
`chat_type = "group" if group_info is not None else "private"` —— **上游还没修**，
更新后这个补丁**必须保留**。

## 2. `core-memory-summary-filter.patch`

**改哪**：`src/A_memorix/core/utils/summary_importer.py`

**现象**：系统通知、bot 自己的话被当成「她说过的话」写进摘要，再回灌进记忆，
于是她开始反复提起自己没说过的事。

**修法**：摘要时过滤 bot 消息（`filter_mai=True`）与命令消息（`filter_command=True`）。

**上游状态**：上游在 2026-10-15 之后**没动过这个文件** → 干净合入，不冲突。

## 3. `plugin-impression-card-session-scope.patch`

**改哪**：`plugins/com_0-hz_impression-card/plugin.py`

**现象**：私聊里说的事，出现在群里的上下文里。

**根因**：印象卡片的 `affinity` 表**主键是宿主的 `person_id`**（一个人一份），
插件自己的 config 注释就写着「**跨私聊/群聊共用一份**」。
于是私聊沉淀的印象被群直接读到。实测群里的 planner 推理原文：

> `It mentions 20块, 私聊黏人, 戳脑袋, 四个赞, 炸鸡`

卡面正文更直接：「张口就是宝宝、爱你」「二十块那笔」「四个赞就慌得很」「炸鸡也继续欠着」。

**修法**：卡片主键改成 **人 + 会话** = `person_id#stream_id`。

- `PersonRef.person_id` **保持宿主原始 ID 不变**（`ctx.db` / `ctx.person` /
  `knowledge.search` 都用它），**另加** `scope_id` 与 `card_key`，
  只让 `affinity` 表的存取走 `card_key`；
- 拿库里 `person_id` 回查宿主的地方要先 `_split_scope()` 拆出 raw；
- 按显示名查卡时**优先当前会话那张**；
- ⚠ **兜底分支绝不能回退到别的会话那张** —— 这一点我们第一版就踩了：
  加了 scope 过滤但保留「没匹配就按显示名唯一匹配」的兜底，结果群作用域照样取到私聊那张卡。
  现在当前会话没有卡就**返回无**，让它按本会话素材重建。

**迁移**：旧的「无会话维度」行要迁到私聊作用域，否则私聊那份印象白丢：

```sql
UPDATE affinity SET person_id = person_id || '#<私聊session_id>' WHERE person_id NOT LIKE '%#%';
```

## 4. `plugin-better-diary-continuity-scope.patch`

**改哪**：`plugins/org_orge-8_better-diary/plugin.py`

**现象**：**公开发布**的日记里混进私聊内容。

**根因**：跨天「连续性」会把前几篇日记的线索拼进下一次的提示词
（`build_continuity_line`：上一次写到 / 还在聊的话题 / 手头还在进行的事 / 还没个结果的），
状态存在**一个全局文件** `continuity.json`。
那个文件里 11 条 `important_events` 有 **8 条是私聊内容**，
`ongoing_projects` / `unresolved_items` 里就是「二十元交易争议」「画窗台上的自己」。

→ **修复前**从私聊取材写的日记把私聊事实沉淀进全局文件，
之后的**群**日记引用这些线索 → 跟着正文**发到公开空间**。

实测 2026-10-21 23:30 那条群日记：选材 100% 来自群，正文却出现
「二十元交易争议也还悬着」「窗台上的画像还没画出来」。

**修法**：连续性**按取材范围分桶**，文件名 `continuity-<md5(target_chats)[:10]>.json`，
不同 `target_chats` 各存各的。

**判据（通用）**：**「当天素材干净」不等于「成稿干净」**。
任何把历史内容拼进提示词的机制（连续性、摘要回灌、未解决事项、长期记忆）
都要单独查一遍会话隔离 —— 日记提示词的输入只有四块：
当日素材 / 人设 / 篇幅 / 连续性，所以**连续性是唯一的私聊入口**。

## 打补丁的顺序

```bash
cd MaiBot
# 核心两个先打（顺序无所谓）
git apply /path/to/xuxingjiu-maibot/patches/core-platform-io-group-target-fallback.patch
git apply /path/to/xuxingjiu-maibot/patches/core-memory-summary-filter.patch

# 插件两个要进插件目录打
cd plugins/com_0-hz_impression-card
git apply /path/to/xuxingjiu-maibot/patches/plugin-impression-card-session-scope.patch
cd ../org_orge-8_better-diary
git apply /path/to/xuxingjiu-maibot/patches/plugin-better-diary-continuity-scope.patch
```

> ⚠ `plugins/` 在 MaiBot 的 `.gitignore` 里（`/plugins/*`），
> 所以插件目录本身不是 git 仓库时 `git apply` 也能用（按文件路径 apply 即可）。

**打完必须重启 MaiBot**：配置是热重载的，但**插件代码和核心代码不是**。
